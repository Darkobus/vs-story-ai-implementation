Improvements — so players actually use it

Concrete improvements ordered by impact / effort, with what is already done. The quality fixes (threshold, multilingual embeddings, cosine) and the player-facing ones (help, citations, quieter events) are in; what is left is mostly better retrieval and housekeeping.

1 Relevance threshold + “I don't know” done

The most important fix. query() always returns the nearest chunks, even when the question has nothing to do with the database, and the bot used to paste that junk into the prompt and answer confidently. Now only chunks closer than RAG_MAX_DISTANCE are used; if none qualify, the prompt tells the model to say it has no reliable information (rule 5 in the assistant prompt). 

hits = kb.search(wiki_collection, question, n_results=5)      # Hit(text, distance, metadata)
relevant = [h for h in hits if h.distance < RAG_MAX_DISTANCE]   # default 0.5; "off" disables
Still to do: calibrate it. 0.5 is a starting point, not measured on the rebuilt knowledge base. Run python -m tools.dbcheck "jak zrobić brąz" "gdzie znaleźć miedź" ... with questions that should and should not match, and set the threshold just above the good hits. Too many “I don't know” answers → raise it; junk still getting through → lower it.

2 Multilingual embeddings done

The old chain was: Polish question → LLM translates it to English → embedding → search. The embedding model is now bge-m3, which puts Polish and English in the same vector space, so the question is searched as written. The translation call is off by default (RAG_TRANSLATE=1 brings it back). Details: LLM.

Embeddings run in Ollama on the game server, so retrieval no longer depends on the gaming PC being on. The collection records its embedding model, and the bot refuses to search it with a different one.

3 A clear trigger + help done

  • The trigger is case-insensitive and accepts AI …, ai: …, ai, … and @ai ….
  • AI pomoc / AI help / AI ? answers with a fixed explanation and two example questions — no LLM call.
  • Every join greeting ends with a fixed hint: “Napisz „AI pomoc”, żeby zobaczyć, jak ze mną rozmawiać.” (JOIN_HINT).

Details: Bot.

Long term, the cleanest trigger is an in-game /ai command added by a server mod (like EventLogger). Bigger project, worth keeping in mind.

4 Cosine metric done

The collection used Chroma's default l2 because no metric was set. The rebuilt collection, vintage_story_kb, is created with "hnsw:space": "cosine", and opening an l2 collection is refused. This was done in the same rebuild as #2. See RAG.

5 Hybrid search + reranking open

Pure vector search struggles with exact names and codes (ingot-tinbronze, a specific block name). Two upgrades:

  • Hybrid (vector + keywords / BM25): combines meaning with literal name matching.
  • Reranking: fetch 15–20 candidates by vector, then a small cross-encoder re-sorts them and keeps the best 3.

6 Citing sources done

Answers grounded in the knowledge base end with up to two sources, so players can check them: (źródło: wiki „Bronze”) or (źródła: wiki „Bronze”, dane gry „tinbronze”). Nothing is cited when no chunk passed the threshold. CITE_SOURCES=0 turns it off.

Possible follow-up: wiki chunks also carry a url. Chat cannot show links nicely, but a AI źródło command could print the full URL of the last answer's source.

7 Less spam (optional events) done

Every kind of message is now under control in .env:

EVENT_REACTIONS=join,leave,storm   # also: death, kill; or "all" / "none"
TIPS_ENABLED=1
TIPS_MIN_MINUTES=30                # was every 5–15 minutes
TIPS_MAX_MINUTES=60

Deaths and kills are off by default. Tips are now built from a random knowledge-base chunk, so they are grounded in real data (see Bot).

Possible follow-up: skip tips while nobody is online. The bot only sees joins and leaves since it started, so this needs the player list from the server (RCON) rather than counting events.

8 Security done mostly

  • Secrets out of the code — done. The RCON password, hosts and the Gemini key come from .env (git-ignored; .env.example lists them). The Gemini key is sent in a header, not the URL. The old password is still in the git history, so it must be changed on the server.
  • Command whitelist — done, now an exact match: time or weather, no arguments (see Bot).
  • Per-player rate limit — done: one question per CHAT_COOLDOWN_SEC (default 10 s), which also caps Gemini cost.
  • Prompt injection — open. The player's message goes into the prompt; “ignore the rules and…” attempts are only limited by the whitelist, which keeps the worst case harmless.

9 Persistent per-player memory open

Conversation memory (the last 3 exchanges per player) lives in RAM and is lost on restart. It could be saved to disk (SQLite, or a small JSON file per player) with a size limit and expiry.

Do not overdo it — a helper bot does not need to remember everything. A few recent exchanges per player is plenty, and less context means faster and cheaper answers.

10 Code structure, tests, CI partly

Done:

  • The shared vsai/ package (config, embeddings, knowledge base, RCON) used by the bot, ingest and tools.
  • Unit tests (tests/unit/, including a real temporary ChromaDB), and CI running ruff, mypy and pytest.
  • The retired fine-tuning code moved to archive/.

Open: watchdog.py is still one file. Splitting it along the 5 steps from Architecture would make it easier to find your way around:

bot/
├── watchdog.py    # main(): log loop + dispatch
├── chat.py        # trigger, toxicity, cooldowns

11 Mod assets in the knowledge base open

Ingest reads vanilla survival/ assets only. Mods keep their assets in the same layout inside the archives in Mods/. Supporting them means extracting the archives, reading each mod's asset folders, and tagging chunks with the mod as their source — and changing the “replace by asset type” cleanup, which today would also delete vanilla chunks of that type.

✓ Done along the way

  • Answers no longer wait for the next log line — a thread pool plus a thread-safe RCON client.
  • The bot survives container restarts — the log stream reconnects instead of exiting.
  • No zero vectors — embedding failures raise an error; ingest skips and counts the failed batch.
  • No stale or colliding chunks — IDs include the asset path, and re-ingest replaces a source's chunks.
  • Cleaner wiki text — infoboxes kept as data, image sizes, file links and translation tags removed.
  • Memory remembers the questions too, not only the bot's answers.

→ Suggested next steps

  1. Rebuild and calibrate — ingest into the new collection on the server, then tune RAG_MAX_DISTANCE (#1).
  2. Watch real usage — read the bot's log for a week: which questions get “I don't know”, which sources get cited, whether tips get skipped a lot.
  3. Hybrid search + reranking (#5) — the next big jump in answer quality, especially for exact item names.
  4. Split watchdog.py (#10) and mod assets (#11) — when they start to matter.
