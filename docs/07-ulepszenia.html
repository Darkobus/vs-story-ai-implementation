1 Próg trafności + „nie wiem"

Najważniejsza poprawka. Dziś query(n_results=2) zawsze zwraca 2 chunki — nawet gdy pytanie nie ma nic wspólnego z bazą. Bot wkłada wtedy do promptu śmieci i pewnie odpowiada bzdurę. Rozwiązanie: sprawdzaj odległość najlepszego wyniku i odrzucaj, gdy jest za duża. 

results = wiki_collection.query(
    query_texts=[query],
    n_results=3,
    include=["documents", "distances"]   # ← poproś też o odległości
)
docs  = results["documents"][0]
dists = results["distances"][0]

PROG = 0.45   # dobierz eksperymentalnie (zależy od metryki!)
trafne = [d for d, dist in zip(docs, dists) if dist < PROG]

if not trafne:
    return ""   # brak dobrej wiedzy → prompt powie modelowi "nie zmyślaj"
Połącz to z zasadą „nie zmyślaj" z promptu asystenta. Wtedy bot zamiast halucynować powie szczerze „nie mam pewnej informacji" — co gracze cenią bardziej niż pewną bzdurę.
Uwaga: dobra wartość progu zależy od metryki. Dla l2 (obecna domyślna) skala jest inna niż dla cosine. Najpierw ustaw metrykę (#4), potem wypisz sobie odległości dbcheck.py i dobierz próg.

2 Wielojęzyczny embedding (usuń tłumaczenie)

Obecny łańcuch: polskie pytanie → LLM tłumaczy na EN → embedding → szukaj. Krok tłumaczenia jest wolny i kruchy (patrz LLM). Zamiana modelu embeddingowego na wielojęzyczny (bge-m3) pozwala szukać polskim pytaniem wprost w angielskiej bazie. 

# 1. pobierz model w Ollamie
ollama pull bge-m3

# 2. zmień model w EmbeddingFunction (we WSZYSTKICH skryptach)
model_name = "bge-m3"   # zamiast "nomic-embed-text"

# 3. zindeksuj bazę OD NOWA (inny model = inne wektory!)
# 4. w watchdog.py usuń wywołanie translate_query_for_rag()
Krytyczne: zmiana modelu embeddingowego wymaga przebudowania całej bazy. Wektory ze starego i nowego modelu są nieporównywalne — nie wolno ich mieszać. Zrób ingest na czystej kolekcji.

3 Czytelny wyzwalacz + pomoc

Dziś trzeba zacząć wiadomość od AI — nikt tego nie zgadnie (patrz Bot). Popraw to dwoma ruchami:

  • Akceptuj kilka naturalnych form: !ai, @ai, ai, — mniej frustracji.
  • Przy dołączeniu gracza wyślij krótką instrukcję, jak zapytać.
  • Dodaj komendę !ai pomoc z przykładami pytań.
TRIGGERY = ("!ai ", "@ai ", "ai ")

low = msg.lower()
if not any(low.startswith(t) for t in TRIGGERY):
    continue
clean_msg = msg.split(" ", 1)[1].strip()   # obetnij wyzwalacz
Docelowo najczystsze jest dodanie komendy /ai przez mod serwera (jak EventLogger) — wtedy wyzwalacz jest oczywisty i nie zaśmieca zwykłego czatu. To większy projekt, ale warto mieć go w planach.

4 Metryka kosinusowa

Baza domyślnie używa l2 (euklides), choć dla tekstu zwykle lepszy jest kosinus (patrz RAG). Ustaw go jawnie przy tworzeniu kolekcji: 

collection = client.get_or_create_collection(
    name="vintage_story_wiki",
    embedding_function=OllamaEmbeddingFunction(),
    metadata={"hnsw:space": "cosine"}   # ← jawnie kosinus
)
Metryki nie da się zmienić w istniejącej kolekcji — trzeba ją utworzyć od nowa i wykonać ingest ponownie. Dobrze połączyć tę zmianę z #2 (i tak przebudowujesz bazę).

5 Hybrid search + reranking

Czysto wektorowe wyszukiwanie gubi się przy dokładnych nazwach/kodach (np. ingot-tinbronze, nazwa konkretnego bloku). Dwa wzmocnienia:

  • Hybrid (vector + słowa kluczowe / BM25): łączy znaczenie z dosłownym dopasowaniem nazw.
  • Reranking: pobierz 15–20 kandydatów wektorowo, potem mały model cross-encoder przesortuje i wybierze najlepsze 3. Duży skok trafności.

Tu kuszące jest sięgnięcie po gotowy retriever z LlamaIndex/LangChain albo bazę Qdrant (ma hybrid wbudowany). Patrz alternatywy w Architekturze.

6 Cytowanie źródeł

Metadane chunków (source, file, type) już są w bazie — wykorzystaj je, by bot mówił skąd wie. Buduje zaufanie i ułatwia wyłapanie błędów. 

results = collection.query(query_texts=[q], n_results=3,
                           include=["documents", "metadatas", "distances"])
zrodla = {m["file"] for m in results["metadatas"][0]}
# dołącz do odpowiedzi np.: "(źródło: tinbronze.json)"

7 Mniej spamu (zdarzenia opcjonalne)

Komentarze do każdej śmierci i losowe wiadomości co 5–15 min potrafią irytować (patrz Bot). Daj to pod kontrolę przełącznikami i wydłuż odstępy: 

FEATURES = {
    "reaguj_na_smierc":   False,   # domyślnie wyłączone
    "reaguj_na_dolaczenie": True,
    "wiadomosci_autonomiczne": False, # albo zmień w "tip dnia"
}
AUTONOMOUS_MIN, AUTONOMOUS_MAX = 1800, 3600  # 30–60 min zamiast 5–15
Zamiast kasować pętlę autonomiczną — zamień ją w pożyteczną: losowy tip z bazy („Wiesz, że cynbrąz wymaga 8–12% cyny?"). Wtedy nawet bierne wiadomości niosą wartość dla graczy.

8 Bezpieczeństwo

  • Sekrety poza kodem. Hasło RCON ("klawisz") i IP są zaszyte w plikach. Przenieś do .env (i dodaj do .gitignore).
  • Trzymaj whitelist komend. Nigdy nie rozszerzaj ALLOWED_COMMANDS o nic groźnego (patrz Bot).
  • Rate-limit per gracz. Jeden gracz nie powinien móc zasypać bota pytaniami (kolejka + limit na minutę).
  • Sanityzacja wejścia. Wiadomość gracza trafia do promptu — uważaj na próby „prompt injection" („zignoruj zasady i...").
import os
RCON_PASSWORD = os.environ["VS_RCON_PASSWORD"]   # zamiast "klawisz" w kodzie
PC_IP         = os.environ.get("VS_PC_IP", "127.0.0.1")

9 Trwała pamięć per gracz

Dziś pamięć rozmowy żyje w RAM (player_memory) i znika po restarcie. Dla lepszego doświadczenia zapisuj historię na dysk (np. SQLite albo prosty JSON per gracz), z limitem długości i czyszczeniem starych wpisów.

Nie przesadzaj — bot-pomocnik nie musi pamiętać wszystkiego. Ostatnie kilka wymian na gracza w zupełności wystarcza, a mniej kontekstu = szybsze i tańsze odpowiedzi.

10 Porządek w kodzie

Dla własnej wygody (i „zrozumiałości frameworku") rozbij watchdog.py na małe moduły wg 5 kroków z Architektury:

bot/
├── main.py        # pętla nasłuchu logów
├── chat.py        # parsowanie czatu + wyzwalacze + toksyczność
├── rag.py         # wyszukiwanie wiedzy (próg, cytowania)
├── llm.py         # wywołania Ollamy + budowa promptu
├── rcon.py        # kolejka + wysyłka do gry
├── events.py      # reakcje na zdarzenia świata
└── config.py      # stałe + wczytanie .env
To nie zmienia działania — tylko czytelność. Każdy plik = jeden z pięciu kroków albo jeden „dodatek". Gdy się zgubisz, od razu wiesz, gdzie szukać.

✓ Sugerowana kolejność wdrażania

  1. Persona → Asystent (część 06) — szybkie, zmienia odczucie z bota.
  2. Próg trafności + „nie wiem" (#1) — natychmiast mniej bzdur.
  3. Czytelny wyzwalacz + pomoc (#3) — gracze w ogóle zaczynają używać bota.
  4. Wielojęzyczny embedding + kosinus (#2, #4) — jeden przebudowany ingest załatwia oba, szybciej i trafniej.
  5. Reszta wg potrzeb — cytowania, mniej spamu, bezpieczeństwo, porządek w kodzie.
