The bot — watchdog.py

The process that runs all the time: it follows the chat, connects RAG to the LLM and posts the answers. This is “phase B” — the day-to-day work.

1 The main loop — following the logs

The bot has no access to a chat API. Instead it reads the server log as a stream: it runs docker logs -f and handles every new line as it arrives. A simple but effective way to listen in. 

def follow_server_log(on_line, retry_delay=5.0):
    log_cmd = ["docker", "logs", "--tail", "0", "-f", CONTAINER_NAME]
    while True:
        with subprocess.Popen(log_cmd, stdout=subprocess.PIPE, stderr=subprocess.STDOUT, text=True) as process:
            for line in iter(process.stdout.readline, ''):
                if line.strip():
                    on_line(line.strip())       # classify the line, hand work to the pool
        # the stream ended (container restarted) — reconnect instead of exiting
        time.sleep(retry_delay)
Why the reconnect loop matters: when the game container restarts, docker logs -f ends normally. Before, the bot then exited with code 0 — and systemd's Restart=on-failure does not restart a clean exit, so the bot stayed down. Now it simply reconnects.

Chat lines are recognised by a regular expression that picks out the player name and the message:

chat_pattern = re.compile(r"\[Server Chat\].*?\| (.*?): (.*)")

2 How a player calls the bot

The bot does not answer every message — only those addressed to it. The trigger is case-insensitive and accepts a few natural forms: AI jak zrobić brąz?, ai: …, ai, …, @ai …. 

TRIGGER_PATTERN = re.compile(r"^@?ai[\s:,]+(.+)$", re.IGNORECASE | re.DOTALL)

def extract_question(message):
    match = TRIGGER_PATTERN.match(message.strip())
    return match.group(1).strip() if match else None   # None = not for the bot
Players have to know about it. So AI pomoc, AI help or AI ? answers with a fixed how-to-ask message (no LLM call), and every join greeting ends with “Napisz „AI pomoc”, żeby zobaczyć, jak ze mną rozmawiać.” (JOIN_HINT=0 turns that off). A question that merely contains the word, like AI pomoc przy budowie pieca, is still a normal question.

There is also a simple toxicity filter — questions containing banned words are ignored. The list is Polish on purpose, because the players' chat is:

FORBIDDEN_WORDS = ["kys", "idiota", "debil"]
if not question or check_toxicity(question): return

3 From question to answer

Once a question passes the filters, ask_ai() runs — this is where RAG meets the LLM:

def ask_ai(player, prompt):
    hits = fetch_game_knowledge(prompt)                       # 1. RAG with a relevance threshold
    knowledge = "\n".join(h.text for h in hits)
    history = format_history(player)                          # 2. the last 3 Q&A pairs

    system_context = (
        "You are a helpful assistant on a Vintage Story game server. Rules: ..."  # 3. role + rules
        f"Wiki knowledge: {knowledge or NO_KNOWLEDGE} "
        f"Conversation context: {history}"
    )
    ai_reply = generate_text(f"{system_context}\nPlayer {player}: {prompt}\nAnswer:",
                             temperature=0.1)                # 4. Gemini or Ollama
    remember(player, prompt, ai_reply_without_commands)        # 5. remember the exchange
    return f"{ai_reply} {format_sources(hits)}"            # 6. cite: "(źródło: wiki „Bronze”)"

The knowledge lookup searches with the player's own words — the multilingual embedding model matches Polish questions to English chunks directly — and keeps only the chunks that are close enough:

def fetch_game_knowledge(prompt):
    hits = kb.search(wiki_collection, prompt, n_results=5)
    relevant = [h for h in hits if h.distance < RAG_MAX_DISTANCE]   # default 0.5
    return relevant   # [] → the prompt says: admit you don't know
Every lookup logs the distances and sources, e.g. [RAG] Distances: [(0.31, 'game_asset/recipe_alloy/tinbronze.json'), ...] — that is what you tune RAG_MAX_DISTANCE with. The same sources are cited to the player: wiki pages by title, game files by name (dane gry „tinbronze”), at most two. CITE_SOURCES=0 turns that off. The citation is not stored in conversation memory, which lives in RAM: it is lost on restart and is per player.

4 The bridge to the game: logs + RCON

The bot talks to the game over two channels:

  • In (reading): docker logs -f — the stream of chat and events.
  • Out (writing): RCON (the remote console protocol) — sends announce and commands.
rcon = RconClient(config.RCON_HOST, config.RCON_PORT, config.RCON_PASSWORD)

def send_to_game(message):
    clean_msg, commands = parse_reply(message)
    to_run = ([f"announce AI: {clean_msg}"] if clean_msg else []) + commands
    rcon.run(*to_run)        # one connection, several commands; safe from any thread
Why a custom RCON client: vsai/rcon.py uses plain socket timeouts and a lock, so worker threads can send answers directly. The previous library (mcrcon) implements its timeout with signal.alarm, which only works in the main thread — so answers had to wait in a queue for the next log line. The password and port come from .env (VS_RCON_PASSWORD, VS_RCON_PORT, default 42421), never from the code.

5 [CMD: ...] commands — safety

The model can ask for a command to be run by adding a token like [CMD: time] to its answer. The bot extracts it but runs only an exact match from the whitelist — the key safeguard: 

ALLOWED_COMMANDS = ["time", "weather"]

def parse_reply(message):
    commands = []
    clean_msg = message.replace('"', '').replace('\n', ' ')
    match = CMD_PATTERN.search(clean_msg)
    if match and match.group(1).strip() in ALLOWED_COMMANDS:   # exact match, no arguments
        commands.append(match.group(1).strip())
    return CMD_PATTERN.sub('', clean_msg).strip(), commands
Why the whitelist is sacred: without it, the model (or a player who talks it into something) could run ban, give or op. An exact match also matters: a prefix check would let time set night through. With the whitelist, the worst the bot can do is report the time or weather.

6 Threads and cooldowns

MechanismThe problem it solves
Thread pool (4 workers)An LLM call takes seconds. Questions and reactions run in the pool, so reading the log never waits for the model.
Per-player chat cooldownOne player cannot flood the bot: one question per CHAT_COOLDOWN_SEC (default 10 s).
Event cooldownsThe same event (a given player's join, death…) triggers a reaction at most every 30 s.
LocksMemory, cooldowns and RCON are shared between worker threads, so each is guarded by a lock.
 
def is_on_cooldown(key, seconds=EVENT_COOLDOWN_SEC):   # True = too soon, skip
    now = time.time()
    with cooldown_lock:
        if now - cooldowns.get(key, 0) < seconds:
            return True
        cooldowns[key] = now
        return False

7 Reacting to world events

Besides chat, the bot reacts to events it spots in the log: a player joining or leaving, a temporal storm starting or ending, and — thanks to the EventLogger mod — a player dying or killing a creature. Which of these the bot comments on is set by EVENT_REACTIONS (default join,leave,storm; deaths and kills are off, because a comment on every one of them quickly becomes spam). 

join_pattern         = re.compile(r"\[Server Event\] (.+?) \[.+\] joins\.")
player_death_pattern = re.compile(r"\[Server Event\] \[WATCHDOG\] PLAYER_DEATH (.+?) by (.+)")  # from the mod

match = join_pattern.search(line)
if match and "join" in EVENT_REACTIONS and not is_on_cooldown(f"join_{player}"):
    submit(react_to_event, "join", player)

Gameplay tips

Every 30–60 minutes (TIPS_MIN_MINUTES/TIPS_MAX_MINUTES; TIPS_ENABLED=0 turns them off) the bot picks a random chunk from the knowledge base and asks the model to turn it into one short tip — or to answer SKIP if the chunk is not tip material (a list of block codes, say). The tip is cited like an answer.

Why not just ask the model for “a tip”? That is what the bot used to do, through the normal question path. With the relevance threshold, a generic “write a tip” query matches nothing closely, so the model would be told it has no reliable information — or, without the threshold, it would invent a tip from memory. Starting from a real chunk keeps tips grounded and varied.
