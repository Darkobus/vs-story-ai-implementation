1 Główna pętla — nasłuch logów

Bot nie ma dostępu do API czatu gry. Zamiast tego czyta logi serwera jak strumień — odpala docker logs -f i czyta każdą nową linię na bieżąco. To prosty, ale skuteczny trick „podsłuchu". 

log_cmd = ["docker", "logs", "--tail", "0", "-f", CONTAINER_NAME]
process = subprocess.Popen(log_cmd, stdout=subprocess.PIPE, text=True)

for line in iter(process.stdout.readline, ''):   # czytaj linia po linii, w nieskończoność
    flush_rcon_queue()           # wyślij zaległe odpowiedzi z kolejki
    match = chat_pattern.search(line)
    if match:
        player, msg = match.group(1), match.group(2)
        ...

Linie czatu rozpoznaje wyrażenie regularne, które wyłuskuje nick i treść:

chat_pattern = re.compile(r"\[Server Chat\].*?\| (.*?): (.*)")

2 Jak gracz wywołuje bota (ważne!)

Bot nie odpowiada na każdą wiadomość — reaguje tylko, gdy wiadomość zaczyna się od prefiksu AI : 

if player in ["AI", "SYSTEM"] or not msg.startswith("AI "):
    continue                 # ignoruj wszystko bez prefiksu "AI "
clean_msg = msg[3:].strip()    # obetnij "AI " i zostaw samo pytanie
To jest najmniej oczywista rzecz dla graczy. Żeby zagadać do bota, trzeba napisać dokładnie AI jak zrobić brąz?. Nikt tego nie zgadnie bez instrukcji. W Asystencie i Ulepszeniach proponujemy czytelniejszy wyzwalacz (komenda !ai lub @asystent) plus powitanie tłumaczące, jak korzystać.

Jest też prosty filtr toksyczności — wiadomości z zakazanymi słowami są ignorowane:

FORBIDDEN_WORDS = ["kys", "idiota", "debil"]
if check_toxicity(clean_msg): continue

3 Od pytania do odpowiedzi

Gdy pytanie przejdzie filtry, wykonuje się funkcja ask_ai() — to tutaj spina się RAG z LLM:

def ask_ai(player, prompt):
    knowledge = fetch_game_knowledge(prompt)        # 1. RAG: tłumacz PL→EN, szukaj w bazie
    history  = " | ".join(player_memory[player][-3:]) # 2. pamięć: ostatnie 3 wiadomości

    system_context = (
        "Jesteś asystentem w grze Vintage Story. ..."      # 3. instrukcja + zasady
        f"Wiedza z Wiki: {knowledge} Kontekst: {history}"
    )
    data = {"model": MAIN_MODEL, "prompt": f"{system_context}\nGracz: {prompt}", ...}
    ai_reply = ollama_generate(data)                 # 4. zapytaj model
    player_memory[player].append(f"AI: {ai_reply}")    # 5. zapamiętaj odpowiedź
    return ai_reply

A samo wyszukiwanie wiedzy (RAG) wygląda tak — z krokiem tłumaczenia po drodze:

def fetch_game_knowledge(prompt):
    translated = translate_query_for_rag(prompt)     # PL → EN (bo baza jest po EN)
    results = wiki_collection.query(query_texts=[translated], n_results=2)
    return "\n".join(results['documents'][0])
Pamięć rozmowy (player_memory) trzyma ostatnie wiadomości w RAM-ie — znika po restarcie bota i nie jest dzielona między graczy. Dla prostego bota wystarcza; trwałą pamięć omawiamy w Ulepszeniach.

4 Most do gry: logi + RCON

Bot komunikuje się z grą dwukanałowo:

  • Wejście (czytanie): docker logs -f — strumień zdarzeń i czatu.
  • Wyjście (pisanie): RCON (protokół zdalnej konsoli) — wysyła announce i komendy.
with MCRcon("127.0.0.1", "********", port=42421) as mcr:
    mcr.command(f"announce AI: {clean_msg}")   # wyślij odpowiedź na czat
    for cmd in commands_to_run:
        mcr.command(cmd)                       # wykonaj np. "time set day"
Bezpieczeństwo: hasło RCON ("********") i adresy IP są zaszyte na sztywno w kodzie. To zła praktyka — powinny trafić do pliku .env / konfiguracji poza repozytorium. Patrz Ulepszenia.

5 Komendy [CMD: ...] — bezpieczeństwo

Model może w odpowiedzi poprosić o wykonanie komendy, wstawiając token [CMD: time]. Bot go wyłuskuje, ale wykonuje tylko komendy z białej listy — to kluczowe zabezpieczenie: 

ALLOWED_COMMANDS = ["time", "weather"]   # tylko te wolno wykonać

match = re.search(r'\[CMD:\s*(.*?)\]', message)
if match:
    cmd = match.group(1)
    if any(cmd.startswith(a) for a in ALLOWED_COMMANDS):  # whitelist!
        commands_to_run.append(cmd)
    clean_msg = re.sub(r'\[CMD:\s*.*?\]', '', message)  # usuń token z tekstu
Dlaczego whitelist jest święty: bez niej model (albo gracz, który go „przekona") mógłby wykonać ban, give czy op. Biała lista = bot może najwyżej zmienić czas/pogodę. Trzymaj się tej zasady.

6 Wątki, kolejka i cooldowny

To jest cała „skomplikowana otoczka" wokół prostej pętli. Trzy mechanizmy:

MechanizmProblem, który rozwiązuje
Wątki (threads)Reakcja na śmierć/burzę woła LLM (wolne). Bez osobnego wątku zablokowałoby to czytanie czatu.
Kolejka RCONRCON nie lubi wielu wątków naraz. Wątki wrzucają wiadomości do kolejki, a wysyła je tylko główny wątek.
CooldownyZapobiega spamowi — ten sam typ zdarzenia nie wywoła reakcji częściej niż co 30 s.
 
rcon_queue = queue.Queue()   # wątki wrzucają tu, główny wątek opróżnia

def is_on_cooldown(event_key):       # True = za wcześnie, pomiń
    if time.time() - event_cooldowns.get(event_key, 0) < 30:
        return True
    event_cooldowns[event_key] = time.time()
    return False

7 Reakcje na zdarzenia świata

Poza czatem bot reaguje na zdarzenia wyłapane z logów: dołączenie/wyjście gracza, burza temporalna, a dzięki modowi EventLogger także śmierć gracza i zabicie stwora. Jest też pętla autonomiczna wysyłająca losowe wiadomości co 5–15 minut. 

join_pattern  = re.compile(r"\[Server Event\] (.+?) \[.+\] joins\.")
death_pattern = re.compile(r"\[WATCHDOG\] PLAYER_DEATH (.+?) by (.+)")  # z moda

if join_pattern.search(line) and not is_on_cooldown(f"join_{player}"):
    threading.Thread(target=react_to_event, args=("join", player)).start()
Dla graczy to może być męczące. Komentarze do każdej śmierci i losowy spam co kilka minut potrafią irytować. Rekomendacja: uczynić to opcjonalnym i rzadszym (przełącznik w configu) — patrz Ulepszenia. Mod EventLogger (C#) jest opisany jako osobny element w mapie plików.
